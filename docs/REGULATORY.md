# 규제 트랙 정리 · 파일럿 준비 (요약)

> 본 문서는 구현된 플랫폼의 규제 관점 요약이다. 상세 초안은 `1.doc/1-4 추가문서/규제임상법무_초안집.md`,
> 단일 소스 데이터는 `web/src/lib/regulatory.ts`(관리자 `/admin/regulatory`에 렌더)를 참조한다.
> 모든 분류·일정은 **가정·초안**이며, 실제 SaMD 해당성·등급은 식약처 사전상담에서 확정한다.

## 1. 의도된 사용 (Intended Use)

- **목적**: 요화학(소변) 검사와 개인 건강기록(PHR)을 결합해 만성질환 위험을 선별·계층화하고,
  사용자의 이해·생활관리·의료진 상담 연계를 돕는다.
- **대상**: 일반 이용자(건강관리), 의료진(모니터링 보조), 시설/검진센터.
- **환경**: 가정·검진센터·의료기관 등 인터넷 연결 환경.
- **사용 제외**: 확정 진단·처방·응급의료 판단을 대체하지 않는다. 최종 임상 판단은 의료진에게 있다.

## 2. 트랙 분리 (SaMD 후보 / 웰니스)

| 기능 | 트랙 | SaMD 가능성 |
| --- | --- | --- |
| 위험계층화(질환별 위험점수·등급) | 의료기기 후보 | 높음 |
| 표준 위험등급(KDIGO형) | 의료기기 후보 | 높음 |
| 설명 리포트(SHAP 근거) | 의료기기 후보(종속) | 중간 |
| 측정 수집·품질보정 | 검토 필요 | 낮음~중간 |
| 생활관리·교육 콘텐츠 | 웰니스 | 낮음 |
| 게이미피케이션·미션 | 웰니스 | 낮음 |

- **분리 기전**: 데이터 모델의 `risk_assessment.is_samd_output` 플래그로 SaMD 출력을 식별·로깅하고,
  UI 전반에 "선별 정보·비진단" 고지문을 표기한다. 웰니스 선출시 + 의료기기 인허가 병행 준비가 가능한 단계적 출시 구조.

## 3. 구현된 규제·품질·보안 통제

- **표시·톤**: 전 화면 비진단·비응급 고지, "의료진 상담 권유" 권고 톤(지시·응급 표현 회피).
- **설명가능성**: 질환별 SHAP 기여요인 + 이중 채널 설명(사용자/임상) + 가이드라인 참고.
- **감사로그**: PHI 열람(`view_phi`)·콘텐츠 게시·의료진 승인·인증 보안 이벤트 불변 기록.
- **접근통제**: RBAC, 의료진 승인 게이트(면허 확인 후 활성화), 세션·동의 관리.
- **보안(Step 8)**: 보안 헤더(CSP·HSTS·X-Frame-Options 등), 로그인 레이트리밋, 구조화 로깅, 헬스체크(`/api/health`).
- **변경관리**: 모델 버전(`model_version`) 추적, 배포 게이트(가정).

## 4. 인허가 준비 문서 (착수 현황)

일부 착수(의도된 사용·SW 요구사항·V&V·사이버보안·라벨링) / 작성 필요(위험관리 파일·SW 생명주기·임상 평가·사용적합성).
상세 상태는 `/admin/regulatory`의 "인허가 준비 문서" 섹션 참조.

## 5. 임상 검증 · 파일럿 단계

1. **내부 검증(진행)** — 알고리즘 재현성·E2E 사용자 여정·보안 점검
2. **시설/검진센터 파일럿(예정)** — 실사용 데이터로 유용성·사용성 평가
3. **임상적 평가(예정)** — 표준검사 대비 성능·안전성 근거 수집
4. **SaMD 인허가 신청(예정)** — 기술문서·임상평가 패키지 제출

## 6. 파일럿 준비 — V&V 스모크 테스트

사용자 여정 8단계(가입→동의→측정→다질환 분석→설명/SHAP→케어액션→알림→게이미피케이션→미션→SaMD 플래깅)를
실DB로 검증하는 자동 스모크 테스트를 제공한다. 일회성 테스트 계정을 생성·검증 후 cascade 삭제한다.

```bash
cd web && npm run smoke   # 13개 체크, 전부 통과 시 exit 0
```
